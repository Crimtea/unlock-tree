# UnlockTree · 任务解锁树

一个用「前置条件」驱动任务解锁、并按依赖层级可视化任务进度的前端工具。它把多种解锁关系统一成一种条件模型，支持任务的完成/撤销、级联校验、拖拽调整位置、预览/编辑模式切换，以及任务数据的导入导出。

## 核心概念：条件组模型

任务的前置条件用 `Requirement = string[][]` 表示：

- **条件组之间为「且」**：所有条件组都必须满足；
- **组内任务之间为「或」**：任意一项完成即满足该组。

因此五种解锁模式都可以用同一个结构表达：

| 模式 | 表达方式 | 含义 |
| --- | --- | --- |
| 一解锁一 | `[[A]]` | 完成 A 才能解锁 B |
| 一解锁多 | 多个任务都写 `[[A]]` | 完成 A 后解锁 B、C、D 等多个任务 |
| 多解锁一 | `[[A], [B]]` | A 和 B 都完成才能解锁任务 |
| 可选任务 | `[[A, B]]` | A 或 B 任意一个完成即可解锁任务 |
| 必须 + 可选 | `[[A, B], [C]]` | A/B 至少一个完成，且 C 完成，才能解锁任务 |

## 功能特性

- **进度可视化**：按依赖深度从左到右分层展示任务树（有向无环图），节点区分「已完成 / 可开始 / 未解锁」，并标注解锁模式；支持 5%–200% 缩放与一键适应窗口。在树图区域内滚动鼠标滚轮即可缩放（以光标位置为中心），在空白处按住鼠标拖拽可平移预览区域，水平/垂直滚动条均已隐藏。画布四周预留了空白区域，即使上下左右没有节点也可以继续拖拽一段距离，形成类似无限画布的浏览体验。任务树面板始终占满剩余视口高度，页面本身不滚动。
- **完成与级联撤销**：点击节点上的「完成 / 撤销」推进进度；当已完成任务的前置条件不再成立时，会自动改为未完成，并继续向下传播。
- **前置条件编辑**：编辑任务名称、备注和前置条件；保存前拦截会形成循环依赖的条件。
- **拖拽调整位置**：编辑模式下，同列拖到节点上会交换槽位，拖到空白处会直接落位、原位置留空；拖到其他列只改变节点的展示位置，前置条件与解锁关系不变（箭头可能跨列或反向）。节点可以拖进四周留白区，对应负数列与负槽位；拖回依赖深度对应的列会自动清除手动位置。详情面板也提供上移/下移按钮。
- **一键格式化**：编辑模式下点击「一键格式化」，清除所有手动位置，按前置条件的依赖深度把节点从左到右整齐排列；同层节点保留当前上下顺序，槽位重排为连续非负整数。
- **预览 / 编辑模式**：默认进入预览模式，节点可标记完成/撤销，详情为只读文字，不显示编辑控件；切换到编辑模式后可修改任务、拖拽排序、新增/删除和清空进度。
- **数据持久化与交换**：任务数据保存在浏览器 localStorage；编辑模式下可为任务树命名，导出文件名自动包含树名称与日期（如 `unlock-tree-项目规划-20261126.json`）；支持从 JSON 文件导入并还原树名称。

# 安装依赖
pnpm install

pnpm lint

pnpm preview

## 使用说明

1. **查看进度**：默认处于预览模式，点击节点打开详情；前置条件满足时，节点上的「完成」按钮可用。在树图区域滚动鼠标滚轮可缩放（5%–200%，以光标位置为中心；「适应」可按整棵树大小自动缩到合适比例并居中），在空白处按住鼠标拖拽可平移视图；也可使用面板顶部的缩放按钮调整比例，或点击「适应」自动缩放并把整棵树居中显示（即使之前平移过视图也会重新定位）。
2. **切换模式**：点击顶部「预览模式 · 点击切换编辑」进入编辑模式。
3. **编辑任务**：在详情面板修改名称、备注、前置条件；条件组之间的按钮用于切换「且 / 或」语义。
4. **调整位置**：编辑模式下拖拽节点左侧的手柄。同列拖动可上下调整顺序（落在节点上交换、落在空白处落位）；左右拖到别的列只改变显示位置，不会修改前置条件。也可使用详情面板的上移/下移按钮。
5. **一键格式化**：编辑模式下点击顶部「一键格式化」，把因拖拽而错位的节点按依赖深度从左到右重新排列，同层保持当前上下顺序；不影响任务内容与进度。
6. **管理数据**：编辑模式下可修改任务树名称（任务树面板顶部）、新增任务、恢复示例、一键清空进度与清空所有任务。
7. **备份 / 迁移**：使用顶部「导出数据」下载 JSON，文件名格式为 `unlock-tree-树名称-YYYYMMDD.json`（名称为空时使用「未命名任务树」）；使用「导入数据」选择文件，确认后覆盖当前任务、进度与树名称。

> 撤销某个已完成任务，或修改已完成任务的前置条件后，系统会自动重检所有任务。若后置已完成任务的完成条件缺失，也会被改为未完成。

## 数据格式

导出的 JSON 形如：

```json
{
  "version": 1,
  "exportedAt": "2026-11-25T06:00:00.000Z",
  "name": "项目规划",
  "tasks": [
    {
      "id": "t1",
      "title": "需求确认",
      "note": "明确项目目标与验收标准。",
      "requirement": [],
      "completed": true,
      "slot": 0
    },
    {
      "id": "t2",
      "title": "原型设计",
      "note": "完成「需求确认」后解锁。",
      "requirement": [["t1"]],
      "completed": false,
      "slot": 0
    }
  ]
}
```

字段说明：

- `name`：任务树名称，导入时会还原；旧文件可缺省该字段；
- `id`：任务唯一标识；
- `title` / `note`：任务名称与备注；
- `requirement`：前置条件，组间「且」、组内「或」；
- `completed`：是否已完成；
- `slot`：同列内的固定槽位，可为负数，可留空；
- `column`：可选，手动指定的展示列，可为负数；不填时按前置条件的依赖深度自动排列。

导入时同时接受上述格式和纯任务数组。导入前会校验结构，清理重复 ID 与悬空前置条件，拒绝循环依赖，并重新校验完成状态；文件上限为 5 MB。

任务数据保存在浏览器 localStorage 的 `unlock-tree:tasks` 键中，任务树名称保存在 `unlock-tree:name` 键中。

## 设计说明

- **级联校验**采用固定点循环：反复检查所有已完成任务，直到没有任何任务缺失完成条件，保证依赖链上的失效状态被完整传播。
- **布局**默认按依赖深度分层，同列按 `slot` 定位；拖拽产生的 `column` 覆盖仅影响展示位置，不改变解锁关系。槽位是固定位置，任务移走后原位置保留空白，不会自动补位。
- **循环依赖**在编辑前置条件和导入数据时都会被检查，避免产生无法完成的死锁任务。
